Test smells × code smells

Relatório do que foi construído, dos resultados obtidos, do que cada um significa e do que implicam para um possível artigo. Escrito para ser lido sem conhecimento prévio do estudo.

18 de setembro de 2026 · Cristian Ritter · 3 etapas concluídas · 104 testes estatísticos registrados

01

O vocabulário do estudo

Quatro termos aparecem o tempo todo no restante do relatório.

Code smell
Sintoma de problema de design no código de produção — uma classe grande demais (blob), uma classe que só guarda dados (data class), um método que usa mais dados de outra classe que da própria (feature envy), um método longo demais (long method). Não é erro de execução: o programa funciona, mas o código é mais difícil de manter.
Test smell
O mesmo conceito, aplicado ao código de teste. Exemplos: um método de teste com muitas verificações sem mensagem que as distinga (assertion roulette), um teste que exercita várias funcionalidades de uma vez (eager test), um teste que depende de arquivo externo (mystery guest). O estudo usa 13 tipos.
MLCQ
Conjunto de dados publicado em 2020 com anotações de code smell feitas por desenvolvedores profissionais: 14.739 revisões sobre 4.770 trechos de código Java, cada uma atribuindo uma severidade (none, minor, major, critical). É a nossa fonte do lado da produção — e o diferencial dela é ser percepção humana, não cálculo de métrica.
JNose
Ferramenta acadêmica que detecta test smells em código Java. É a nossa fonte do lado do teste.
02

A pergunta e o obstáculo

A pergunta: classes que desenvolvedores profissionais percebem como tendo code smell são testadas por código com mais test smell? Em outras palavras: código de produção ruim anda junto com código de teste ruim?

O obstáculo é que as duas fontes não se falam. O MLCQ diz "este arquivo de produção tem code smell"; o JNose diz "esta classe de teste tem test smell". Para cruzar os dois é preciso saber qual teste testa qual classe — e essa ligação não está escrita em lugar nenhum do código. Ela precisa ser inferida.

Chamamos essa inferência de binding. Ela é o centro técnico do trabalho, porque todo o resultado depende de ela estar certa: se o teste ligado a uma classe não é o teste dela, os test smells que atribuímos àquela classe são de outra.

03

O que foi construído

Etapa 1 Coleta dos test smells JNose executado sobre 451 repositórios Java — os mesmos projetos que o MLCQ anotou —, cerca de 35 horas de processamento. Resultado: 107.535 classes de teste e 2.059.905 ocorrências de test smell. Três defeitos da ferramenta foram encontrados e documentados no caminho, um deles corrompendo o nome da classe em 6,4% dos registros.
Etapa 2 O binding, e a medição dele Três estratégias para ligar arquivo de produção à classe de teste. Em vez de assumir que funcionam, sorteamos 293 pares e conferimos um a um, abrindo os dois arquivos, para medir que fração das ligações é verdadeira.
Etapa 3 A análise Cinco análises independentes sobre o dado resultante, cada uma atacando a pergunta por um ângulo diferente. Todas com testes estatísticos que não exigem distribuição normal, porque os dados são muito assimétricos.

Cada etapa tem um script que reapura todos os números escritos na sua documentação e falha se algum divergir. Nenhum valor citado neste relatório foi digitado à mão.

04

Os resultados

Quatro resultados, cada um com o que foi encontrado, o que significa e o que implica.

01 Não existe associação detectável resultado nulo
rho = 0,047 · intervalo de confiança 95%: [−0,026 , 0,120] · 730 arquivos
O que significa

Rho é uma medida de correlação que varia de −1 a 1, onde 0 é ausência total de relação. O valor encontrado, 0,047, é praticamente zero. O intervalo de confiança diz onde o valor verdadeiro provavelmente está — e ele inclui o zero, ou seja, é compatível com não haver relação nenhuma.

O que implica

Três caminhos diferentes chegaram à mesma conclusão: correlação sobre a escala contínua de severidade, análise de cada um dos 13 test smells separadamente, e comparação entre os casos em que os revisores concordaram que há code smell contra aqueles em que concordaram que não há. Um resultado nulo pode ser azar de operacionalização; três por caminhos independentes apontam para o mesmo lugar.

02 A associação que aparece é tamanho do teste, não qualidade mecanismo medido
contagem bruta: rho 0,092 (p = 0,012) · normalizada por tamanho: 0,047 (não significativo)
correlação da contagem com o tamanho do teste: 0,554
O que significa

Se contarmos simplesmente quantas ocorrências de test smell existem, a correlação aparece e é estatisticamente significativa. Mas um arquivo de teste com 4.668 linhas tem mais ocorrências de tudo que um de 50 linhas — independentemente de qualidade. Quando dividimos a contagem pelo tamanho do teste, a correlação desaparece.

O mecanismo foi medido, não suposto: classe de produção com mais code smell tende a ter teste maior (correlação 0,079 a 0,091), e teste maior tem mais ocorrências de test smell (0,554). O produto dessas duas relações produz uma correlação aparente entre as pontas, sem que exista relação com a qualidade do teste.

O que implica

Se a análise tivesse parado na contagem bruta — que é o mais natural de fazer —, o artigo reportaria uma correlação positiva significativa que é artefato de medição. Esse é um resultado com valor próprio: qualquer estudo que conte ocorrências de test smell sem normalizar por tamanho corre esse risco.

03 A mesma ligação teste→classe mede coisas diferentes conforme a frase que se escreve achado de método
94,8% de acerto para “o teste exercita a classe”
10,1% de acerto para “o teste testa a classe”
O que significa

Uma das estratégias de binding liga teste a classe quando o teste faz referência àquela classe no código. Auditando os pares um a um, ela acerta 94,8% das vezes se a afirmação for "este teste executa código desta classe" — mas apenas 10,1% se for "esta classe é o alvo deste teste".

O caso mais comum ilustra bem: em projetos que usam o framework Camel, todo teste de rota instancia um objeto RouteBuilder como andaime. O teste executa o código dele, mas não o testa. Sozinho, esse arquivo aparece em 20 dos 50 pares que sorteamos naquele estrato.

O que implica

São os mesmos pares e o mesmo instrumento; 85 pontos percentuais separam as duas frases que se pode escrever sobre eles. Isso é um alerta metodológico para toda a linha de pesquisa que liga teste a produção por referência estática — e nenhum dos trabalhos que encontramos reporta precisão dessa ligação.

04 O rótulo do MLCQ é circular com o desenho amostral achado de método
1.227 de 1.227 amostras revisadas na segunda rodada já eram positivas antes
apenas 19 casos com positivo unânime em 4.770 amostras
O que significa

Os autores do MLCQ alocaram revisores extras apenas para amostras que alguém já havia marcado como tendo smell — está descrito no apêndice deles e confirmamos nos dados. Consequência: o número de revisores é resultado do rótulo, não evidência independente dele.

A regra que a literatura costuma usar — "se algum revisor marcou severidade acima de none, a classe tem o smell" — vira, na prática, um detector de quais amostras passaram pela segunda rodada de revisão. E ela descarta justamente o veredito dessa segunda rodada, que em geral não confirmou o primeiro alerta.

O que implica

Qualquer trabalho que use o MLCQ como verdade de referência — inclusive os de detecção automática por aprendizado de máquina, que são a maioria — precisa saber disso. Nosso estudo trata o problema classificando cada amostra pela força da evidência, em vez de escolher um limiar.

Uma quinta análise ficou inconclusiva, e não nula — distinção que o artigo precisa fazer. Ela compara os casos que a maioria dos revisores confirmou contra os casos que ficaram em disputa, e é a única em que os dois grupos passaram pelo mesmo processo de revisão, o que neutraliza o problema do item 04. Mas são apenas 42 casos confirmados: o desenho só detectaria um efeito grande, e os observados são pequenos. Não dá para concluir nada dela — nem a favor, nem contra.
05

Por que este resultado nulo é utilizável

Resultado nulo costuma ser fraco em publicação, porque não se distingue "não existe relação" de "o instrumento era ruidoso demais para enxergá-la". Duas medições feitas antes da análise afastam a segunda explicação.

A precisão do binding foi medida: 94,2%
Sorteamos 293 pares em 6 estratos e conferimos um a um. Com 6% de ligações incorretas, o ruído é pequeno demais para apagar uma relação que existisse. Se a precisão fosse 50%, o nulo não significaria nada.
O poder estatístico foi calculado antes
Poder é a capacidade de detectar um efeito que existe. Calculamos que este desenho detectaria uma correlação de 0,104 ou maior em 80% das vezes. O observado foi 0,047, com teto de intervalo em 0,120.

Somando as duas, o artigo pode afirmar com número: se existe alguma associação entre densidade de test smell e severidade percebida de code smell em classes com teste dedicado, ela é menor que 0,12 — uma correlação tão fraca que não teria consequência prática. Isso é diferente de "não encontramos nada".

06

Onde isso se encaixa na literatura

Levantamento dirigido — não sistemático — feito depois dos experimentos, para saber se alguém já havia reportado essa associação e com que método.

Tahir, Counsell & MacDonell — Class features and test smells APSEC 2016 · CORE C · 20 citações · 5 sistemas, 975 pares O trabalho mais próximo do nosso. Usa a mesma variável de resultado (número de tipos de test smell) e o mesmo teste estatístico, mas o preditor é complexidade calculada por métrica — e não percepção humana. Acharam associação positiva nos cinco sistemas. Não normalizam por tamanho de teste: as palavras "confounder" e "normalize" não aparecem no texto, e eles descrevem a cadeia de tamanho como explicação do achado, não como ameaça a ele.
Spadini et al. — On the Relation of Test Smells to Software Code Quality ICSME 2018 · CORE A · 182 citações · 10 sistemas, >1 milhão de casos de teste A referência da área. Encontraram que código de produção testado por testes com smell tem mais defeitos — desfecho diferente do nosso (defeito, não percepção de design). E controlam por tamanho, citando literatura sobre tamanho como confundidor. O achado deles sobrevive ao controle.
Martins et al. — Difusão de test smells (dataset TSSM) JSEP 2024 · JNose sobre 13.703 sistemas Java Precedente do nosso instrumento: mostra que o JNose em larga escala é aceito na área. Correlaciona test smells com métricas do próprio código de teste, sem tocar em code smell de produção.
Madeyski & Lewowski — MLCQ EASE 2020 · o conjunto de dados de rótulo que usamos Na literatura, o MLCQ é usado para detecção de code smell — aprendizado de máquina, redes neurais, modelos de linguagem. Não encontramos uso dele em estudo de correlação com test smell.

A leitura que encaixa os três estudos

O que prediz test smell parece ser tamanho e complexidade do código — não a percepção de que o código está ruim. Percepção humana e complexidade métrica não são a mesma coisa, e a distância entre as duas é um problema reconhecido na área.

07

O que há de novo, e o que isso vale

Considerando o alvo de veículo com classificação A ou B, vale separar o que é contribuição real do que é apenas trabalho feito.

Contribuições que nenhum dos trabalhos encontrados tem

  • Precisão da ligação teste→produção medida e auditada. Os trabalhos citados usam convenção de nome ou grafo de chamadas e não reportam quanto isso acerta. Nós medimos: 94,2% no binding conservador, e mostramos que uma variante comum cai para 10,1% dependendo da afirmação que se faz.
  • Percepção profissional como preditor, em vez de métrica calculada. O pareamento MLCQ × test smells parece inédito.
  • Poder calculado antes da análise, o que transforma um nulo em limite quantificado.
  • Escala de diversidade — 451 repositórios, contra 5 e 10 dos trabalhos citados.

Avaliação honesta quanto ao alvo A/B

Como artigo de resultado nulo sobre test smell e code smell, a barra A/B é difícil: nulos são publicáveis, mas raramente sozinhos, e o trabalho que contradizemos mais diretamente é de veículo C com baixa citação — derrubá-lo não é feito grande.

O que sustenta A/B é deslocar o eixo: o artigo é sobre validade de medição em estudos de test smell, e o nulo é a demonstração. As três contribuições de método acima — ligação auditada, construto que muda a precisão em 85 pontos, e rótulo circular no conjunto de dados mais usado da área — são problemas que afetam trabalhos já publicados, e é isso que um veículo A/B costuma valorizar mais que mais um resultado de correlação.

Nessa moldura, o nulo deixa de ser o produto e vira a evidência: mostramos que, corrigindo o que os outros não corrigem, a associação some.

08

Limitações

  • O resultado é sobre percepção, não sobre defeito. O MLCQ registra o que desenvolvedores acham do design, não falhas observadas. O artigo precisa dizer isso no título ou no resumo.
  • Cobertura de 37,5%. Conseguimos identificar teste para 1.611 das 4.300 amostras utilizáveis. As restantes misturam classes genuinamente sem teste e falhas do método de ligação — o dado separa os dois casos até onde é possível separar.
  • Mediu-se a precisão, não a cobertura real. Sabemos que fração das ligações feitas está correta; não sabemos que fração das ligações verdadeiras perdemos.
  • A auditoria dos 293 pares foi automatizada, não feita por humano. Uma conferência manual de cerca de 30 pares produziria uma taxa de concordância reportável — é trabalho de aproximadamente uma hora.
  • 104 testes estatísticos foram executados num espaço de cerca de 200 combinações possíveis. Todos estão registrados, inclusive os que não deram em nada, e o artigo precisa declarar regime exploratório.
  • O levantamento de literatura é dirigido, não sistemático. Para submissão A/B, uma revisão com protocolo é trabalho à parte.

Não recomendo rodar mais experimentos. As três operacionalizações já convergiram, e cada teste adicional agrava o problema de comparações múltiplas sem mudar a conclusão. O que falta não é dado — é posicionamento e revisão de literatura.

09

Reprodutibilidade

Todo o material está versionado em repositório público, organizado por etapa. Cada etapa traz um verificador que reapura os números da sua própria documentação e falha se algum divergir — incluindo as tabelas de poder estatístico e os resultados da auditoria de precisão.

As cinco análises da etapa 3 têm pasta própria, com o código que as produziu, os dados de saída e um documento explicando a pergunta, o resultado e a interpretação de cada uma. O levantamento de literatura e a proposta de enquadramento ficam em arquivos separados do estudo, para que opinião não se misture com o que foi medido.
